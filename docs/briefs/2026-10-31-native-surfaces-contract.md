## 1. Where the treaty lives

- `contracts/surface/` becomes a hand-written Rust crate (`korri-surface-treaty`),
  annotated for Typeshare. It imports nothing outside `contracts/`.
- Typeshare writes `contracts/generated/surface.ts` (read-only, regenerated by
  `nix run .#korrid-check`). Surface packages' `logic.ts` imports types from it.
- `contracts/surface/korri-surface.ts` is deleted in the same cut. AGENTS.md's
  map and "Standing decisions" are updated to say this.
- **Every existing model type ports field for field** (`SurfaceGame`,
  `SurfaceStatus`, `SurfaceSettingGroup`, `SurfaceNetwork`, `SurfaceOnboarding`,
  `SurfaceStore`, `SurfaceInvite`, `SurfacePresentation`, …), keeping names, tags,
  optionality and doc comments. Only the changes in section 3 differ.

## 3. New and changed schema (each grounded in an existing producer)

### 3.1 Package (C1)
```
<surface id>/
  main.slint    export component Surface inherits Window   (required)
                export component Overlay inherits Window   (required when the surface draws the gameplay overlay)
  logic.ts      bundled to logic.js; defines globalThis.surface
  fonts/, art/  anything else, referenced only from inside the folder
```
```ts
globalThis.surface = {
  preferences: Record<string, { mark: "shared" | "device"; initial: string }>,
  init(model: SurfaceModel, preferences: Record<string, string>): State,
  update(state: State, message: SurfaceMessage, model: SurfaceModel): { state: State, requests: SurfaceRequest[] },
  view(state: State, model: SurfaceModel): View,          // drives Surface
  overlay?(state: State, model: SurfaceModel): View,      // drives Overlay
}
```
Grounding: the spike's `CONTRACT.md`, plus Pico's and Zone's own `update`
returning requests (`src/state/requests.ts`).

### 3.2 Messages to the surface (C3)
```rust
enum SurfaceMessage {
  Pressed { button: SurfaceButton },    // Up Down Left Right Confirm Back Options Menu System
  KorriPublished,                        // a new model arrived
  PreferenceStored { key: String },      // a RememberPreference completed
}
```
Repeat timing: first repeat after 400 ms, then every 100 ms
(`native-gamepad-mapper.ts`). Grounding: today's `SurfaceInputAction`, plus the
directions and confirm the portal currently turns into DOM focus.

### 3.3 Requests from the surface (C2, D3)
One variant per current `SurfaceHost` method, with identical arguments:
`LaunchGame{game_id, launch_location_id?}`, `RunAction{action_id}`,
`ChangeSetting{setting_id, value}`, `DismissSettingsProblem`,
`ExportIdentityBackup{…}`, `SwitchIdentityFromBackup{…}`,
`SwitchIdentityToNip46{…}`, `DeleteRetiredIdentity{…}`, `DismissIdentityStatus`,
`RunGameAction{game_id, action_id}`, `InvokeGameplayControl{control_id, value?}`,
`DismissGameplayOverlay`, `Retry`, `Dismiss`, `Reload`, `ScanWifi`,
`ConnectWifi{network_id, password?}`, `ConnectHiddenWifi{ssid, password?}`,
`FinishOnboarding`, `OpenStore`, `SearchStore{provider_id, query}`,
`OpenStoreEntry{entry_id}`.

**Removed:** `gameActions(gameId)`.

**New:**
- `FocusGame { game_id: Option<String> }` (D3): the surface reports which game
  has focus. Grounding: `gameActions(gameId)`.
- `RememberPreference { key, value }` (D1): see 3.6.
- `MoveCatalog { … }` (D2): see 3.4.

### 3.4 Cursor catalog (D2)
```rust
enum SurfaceCatalog {
  Loading,
  Error { message: String },
  Empty,
  Ready {
    total: u32,                 // games matching the current query
    window: Vec<SurfaceGame>,   // consecutive games, in query order
    first_index: u32,           // position of window[0] within total
    before: Option<Cursor>,     // absent at the start
    after: Option<Cursor>,      // absent at the end
    query: CatalogQuery,        // the query this window answers
  },
}
struct Cursor(String);           // opaque; the surface never parses it

struct CatalogQuery {
  text: String,                  // empty = no filter
  section: Option<String>,       // only games whose SurfaceGame.section equals this
  order: CatalogOrder,
}
enum CatalogOrder { Korri, Title, MostPlayed, Recent }

// request
MoveCatalog { query: CatalogQuery, from: CatalogFrom, count: u16 }   // count capped at 200
enum CatalogFrom { Start, End, After(Cursor), Before(Cursor), Around(GameId) }
```
- Default: korrid sends `{ text: "", section: None, order: Korri }`,
  `from: Start`, `count: 50`, until a surface asks otherwise.
- `first_index` lets a surface draw "12 / 340" and size a scroll bar.

Grounding:
- `text` is Zone's find draft (`state/games.ts:50`, a case-insensitive
  substring of the title) and Pico's Find query (`pico-library-view.ts:50`, a
  trimmed, case-insensitive substring).
- `section` comes from `SurfaceGame.section` and Pico's `Search.section`.
- `order` is exactly Pico's `PicoOrder`: `korri | title | played | recent`.
- `Around(game_id)` is how both surfaces keep focus on the same game after the
  filter changes (Zone `refilter`).

Seek by a title prefix has no existing consumer, so it is left out. It is
added when a surface needs it.

### 3.5 Focused-game actions (D3)
```rust
SurfaceModel { …, focused_game: Option<FocusedGame> }
struct FocusedGame { game_id: String, actions: Vec<SurfaceAction> }
```
Absent until a `FocusGame` names a game Korri knows.

### 3.6 Preferences (D1)
- The package declares each key with a mark: `shared` follows the person,
  `device` stays on the device (ADR 0018's rule, by kind). It also declares an
  initial value.
- Keys: `[a-z0-9.-]{1,32}`, at most 16 per surface. Values: UTF-8, at most
  256 bytes.
- korrid stores the values per surface id. Shared values are stored on the
  device with the mark kept, and become records (CONTEXT.md, "Record") when
  record sync exists. That sync is not part of this run.
- `init` receives the stored values, or the initial values when nothing is
  stored yet.

Grounding: `pico.font` (`pico-font-preference.ts`, one face id) and
`zone.look` (`zone-look-preference.ts`, one of modern, blend or retro). Both
are a short string under the surface's own name.

### 3.7 Overlay (C6, D5)
When `model.presentation.kind == "gameplay-overlay"`, the shell shows the
package's `Overlay` component, driven by `overlay()`. Notices over a running
game (#179) are out of scope for this run.

### 3.8 Images (C5, D4)
A view value `{ "$image": url }` is decoded once and cached by the shell.
`{ "$image": url, "pico8": "flat" | "vivid" }` asks the shell to quantise the
image to the PICO-8 palette first. The algorithm is ported unchanged from
`surfaces/pico/src/pico8-remap.ts`. No other operation exists in this run.

### 3.9 Verification and limits (C7, D6)
- **At install:**
  - compile `main.slint` (`Surface` and `Overlay`)
  - check the `preferences` declaration
  - sweep every message plus 500 seeded presses against fixture models of 0,
    12 and 10,000 games
  - check every `view()` and `overlay()` against the declared properties
  - write a derived summary into the shell's cache. It is not plugin-host
    schema and is rebuilt when missing.
- **Build and test budgets ([#368](https://github.com/korri-os/korri/issues/368), owner, 2026-11-06):**
  count the calling thread's CPU time, including the load and stuck limits,
  on the thread that runs QuickJS. Keep every limit unchanged. Verification,
  tests and bench logic budgets do not count time descheduled or waiting
  (locks or I/O); this is an accepted cost. Device runtime budgets stay wall
  clock, including amendment A5's slow-call reporting and stuck interrupt.
  Pico and Zone's slow-clock tests keep their existing CPU factors: 28×,
  with the existing /2 allowance. These are calibrated on the i9-11900H
  workstation against the RG353M at 408 MHz, not on arbitrary builders.
  Retired-instruction counts differ by instruction set and are optional
  diagnostics only, never build/test pass marks.
- **At startup:** read one combined index. Never hash.
- **At run time:** each logic call gets 64 MiB of QuickJS heap and 50 ms. A
  surface that breaks either limit is unloaded, and the previous one stays.
  (Replaced by amendment A5, section 11.)

## 6. Shell ↔ korrid wire (added at Platform start, inside the approved section 2)

Both platform workers build against exactly this, so they can work in parallel.

- Existing pattern: `RpcRequest` tagged `app.*` methods over the private
  loopback (`services/korrid/src/lib.rs`), and the native-input WebSocket
  subscription the portal uses (`clients/portal/src/input/native-connection.ts`,
  `services/korrid/src/portal_input.rs`). The shell keeps the native-input
  subscription exactly as the portal uses it.
- `app.surface.model { surface_id }` → the current `SurfaceModel` for that
  surface (catalog window as last moved by that surface).
- `app.surface.watch { surface_id }` on the same authenticated WebSocket: korrid
  pushes `{ revision, model }` whenever the model changes; the shell acks the
  revision like native input. Whole model per push in this run.
- `app.surface.request { surface_id, request: SurfaceRequest }` → `Ok` or a typed
  error; consequences arrive as a new model.
- `app.surface.preferences { surface_id }` → stored preference values.
- surface_id is the package folder id (`pico`, `zone`).
- The capability and port are injected exactly as the portal gets them today; never in a URL, file, log or asset.

## 7. Amendment A1 (owner, 2026-11-02, during review round 1)

### 7.1 Tick (idle time signal)
- New message: `SurfaceMessage::Tick { idle_ms: u32 }`. JSON: `{"_tag":"Tick","idleMs":31000}`.
- The shell sends it to the active surface once a second.
- `idle_ms` is the time since the last `Pressed` it delivered to that surface, or since the surface loaded if none came after. Any `Pressed` resets it to 0.
- Each surface owns its own threshold: Zone 30 s, Pico 45 s, as the portal had. Slint never enters attract or idle on its own; attract shows only while the logic says so.
- The verifier sweeps Tick values in its seeded sequence.

### 7.2 Back cancels (decline marking)
- `decline_action_id: Option<String>` (`declineActionId`), today present only on shared play's Confirm, is set by korrid on every Confirm.
- It is added, optional, to the Busy, ChooseSave and Paused statuses.
- korrid publishes a cancel action, and marks it, for the busy states that offer none today: acquisition "Checking", saves Checking, Reading and Picking. Each cancels what the portal's Back cancelled (`git show main:clients/portal/src/surface/SurfaceRoot.tsx`, lines 334–348).
- A surface's Back runs the marked action, if any, before its own Back handling. Surfaces never infer meaning from action ids.

## 8. Amendment A2 (owner, 2026-11-02): the logic knows its container

Owner: "the correct systemic holistic approach so that the d-pad works just as
a user would expect and that every design follows intrinsic design values."

### 8.1 Resized
- New message: `SurfaceMessage::Resized { width: f32, height: f32 }`, the
  surface window's size in logical pixels (the same units `.slint` lays out
  in). JSON: `{"_tag":"Resized","width":640,"height":480}`.
- The shell sends it once before the first `view()` of every load and switch,
  then on every window size or scale-factor change. `init` keeps its signature;
  the first `Resized` follows it immediately.
- `SurfaceModel.displays` stays as it is: facts about displays for placement
  and for "all" surfaces, never a stand-in for the window.

### 8.2 One plan drives both layout and focus
- A surface computes its layout plan in logic as a pure function of
  (width, height): column counts, which regions sit beside or above each
  other, what is visible. That is the intrinsic-design rule. Its focus graph
  and its `view()` both read that one plan.
- `view()` passes the plan's decisions (columns, arrangement) to `.slint`,
  which draws them. `.slint` may size and space from its own window, but it
  never makes a structural decision that the focus graph does not know.
- Result: a d-pad press always moves to the item drawn in that direction, at
  every size.

### 8.3 Proof required of every surface
- The verifier sweeps `Resized` at 320x240, 640x480, 480x800, 1280x720 and
  1920x1080, including a display list larger than the window.
- For each size, a geometric test: from every focus target, each direction
  moves to the target the plan draws in that direction (nearest along the
  pressed axis, as `spatial-focus.ts` defined it), or stays when none exists.
  This extends the existing "focus is visible" walks; it does not replace
  them.

### 8.4 Regions and exits (refines 8.3; decided 2026-11-02)
- Focus targets are grouped into regions that the plan declares: a row of
  buttons, the tabs, a key grid, a list, the card band.
- Inside a region, a press moves to the target drawn nearest along the pressed
  axis (spatial-focus.ts's rule), or stays when there is none.
- Leaving a region follows the region's declared exits, per direction. An exit
  names a target region and an entry rule: `remembered` (the target the region
  last had focused), `active` (for example the active tab), or `first`. A
  direction with no exit stays.
- Exits are decided by the plan, so they may differ by size. The probe judges
  in-region moves geometrically, and judges exits against the declared exits.
- How a surface declares regions and exits to the probe is set by the shell (a
  generic convention, identical for every surface). Surfaces never write
  their own judge.

## 9. Amendment A3 (owner, 2026-11-02): no design compromise for hardware

- Every surface runs as designed at 60 fps or more on every device Korri
  supports, idle and while the person presses buttons.
- A surface never trims motion, effects or detail to fit weaker hardware.
  Performance is the shell's and the code's job: the renderer, the shell, and
  each package's logic and view cost.
- The pass mark in section 4 becomes: 0 frames over 16.7 ms, idle and with
  presses, on the RG353M and the RG35XX SP, measured with `korri-shell bench`
  on the device.
- The RG353M's 61 % CPU default is removed (owner: "the artificial cap was a
  mistake in the first place").

## 10. Amendment A4 (owner, 2026-11-05): honest launch progress as named steps

- `SurfaceStatus::Busy` gains one optional field, `steps?: SurfaceSteps`,
  with `SurfaceSteps { labels: string[], current: number }`.
- `labels` are the launch's steps in order, in plain user-facing words. They
  list only the steps that really run on this launch.
- `current` is the zero-based index of the step running now.
- The list is fixed for the whole launch. Korri never adds or removes a step
  during a launch. A step that turns out to be unneeded completes at once.
- A surface renders it under Busy's kicker, in its own visual language: a
  segmented bar with one segment per step (done, current and pending can be
  told apart), and "Step i of n · <current label>". The bar shrinks with its
  container, and the text wraps or elides; it never clips.
- Grounding: korrid's launch timeline (`services/korrid/src/launch_timeline.rs`)
  names the stages a launch passes through; the steps are those stages, as
  the person sees them.

## 11. Amendment A5 (owner, 2026-11-06): never change a surface without the person knowing

Owner decision: "Never change a surface unexpectedly without the user
knowing." Before this, one logic call over 50 ms unloaded the surface and
restored the previous one with no notice. On the RG353M, Pico was replaced by
Zone after one 54 ms update at a low idle clock. Logic runs on its own thread,
so a slow call does not stop drawing. This amendment replaces the run-time
rule of section 3.9.

1. **A slow call never unloads a surface.** A call over 50 ms is a
   performance defect. The shell logs it, one journal line per surface per
   message type, rate-limited, and the surface keeps running.
2. **The shell unloads only a surface that cannot work:** a call still
   running after 2 s (the load budget), a crash or exception that kills its
   logic, or a QuickJS heap over 64 MiB.
3. **When the shell unloads a surface, it never switches silently.** It shows
   a notice that names the surface and the reason in plain words (for example
   "Pico stopped responding"), with two actions: try Pico again, or use Zone
   (the previous surface). It switches only on the person's choice. If no
   other surface exists, the notice offers "try again" only. The shell draws
   the notice, because the failed surface cannot. The notice has an
   intrinsic layout and nothing in it clips at the five probe sizes. Its
   actions come from semantic buttons: up and down move the focus, confirm
   takes the focused action, back takes the other surface.
4. Each surface's timing tests stay the guard against slow code: Zone's in
   `clients/shell/tests/zone_package.rs`, and Pico's.
