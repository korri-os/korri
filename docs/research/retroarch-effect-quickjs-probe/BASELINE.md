This is the original report, preserved without rerunning its 50-case matrix.

The current `run.sh` runs the smaller continuation, not the historical matrix.

**Verified blocker: the actual Effect decoder cannot initialize in the empty
QuickJS environment tested here. All 50 runs stop at `TextEncoder is not defined`.**
No replacement decoder, timer shim, URL shim, vendor edit, device operation, or
production runtime change was used. This is an unshipped build-machine experiment,
not an implementation of option A.

## Experiments

| Mode | Source preparation |
| --- | --- |
| `direct` | Original `import { Schema } from "effect"`; all static runtime imports retained |
| `schema` | In-memory change to `import * as Schema from "effect/Schema"`, a public package export; decoder body unchanged |
| `bundle` | Experimental Bun build of the original graph, no minification |
| `bundle-minify` | Same, Bun minification enabled |
| `esbuild` | Experimental esbuild of the original graph, tree-shaking enabled, neutral platform, ES2022 target |

Only the public-import experiment changes an import in a scratch source string.
No repository policy file or installed dependency is changed. Bun's bundle
experiments use virtual modules from the measured graph. esbuild resolves the
original package files and their metadata directly. Neither bundler is korrid's
current runtime preparation path. Neither output is shipped or proposed as an
ahead-of-time plugin artifact.

Each mode has five separately prepared baseline samples, each in a fresh process
and fresh QuickJS runtime. A further five fresh runtimes use a larger experimental
budget. All runs keep the product's 512 KiB stack limit.

| Budget | Initialization outcome | Decoder calls reached | Lowest tested passing heap cap |
| --- | --- | --- | --- |
| 16 MiB / 250 ms (baseline) | 25/25 fail: missing `TextEncoder` | 0 | None |
| 64 MiB / 2,000 ms (probe only) | 25/25 fail: same missing `TextEncoder` | 0 | None |

The representative direct/subpath exception is:

```text
Exception generated by QuickJS: TextEncoder is not defined
    at <anonymous> (plugins/retroarch/node_modules/effect/dist/Encoding.js:492:34)
```

`Encoding.js` initializes `new TextEncoder()` at module scope. This happens
before the policy's decoder is available. A larger heap or deadline does not
resolve this exception. This experiment does **not** establish how much memory
or time a successful decoder needs.

The Oxc path uses the same parser, enum semantic analysis, transformer settings
(including `only_remove_type_imports`), and codegen as `script::transpile_ts`.
Only the plugin's three TypeScript source files need transpilation; the package
exports already select JavaScript. Bundle modes let the external bundler handle
TypeScript instead. The Oxc field near zero in their raw logs is loop overhead,
not evidence that Oxc transpiled a bundle.

Host graph work is a TypeScript-AST probe implementation, not a performance
estimate for a future in-process Rust loader. It excludes Bun startup and final
manifest JSON serialization/write. Those are not hidden inside QuickJS time.

15.184, 9.128, 2.899, 1.317, and 3.015 ms respectively. Bundle preparation includes
build/readback; esbuild also includes CLI startup and version verification.
No cache was dropped. These are repeated build-machine samples, not cold-device
latency measurements. No Android/ARM performance claim follows from them.

**QuickJS decode/render time: unavailable.** The harness would measure each real
`decodeRetroArchPolicy` + `renderRetroArchSettings` call plus JSON serialization,
excluding input JSON parsing, for three rounds. It never reaches those calls.

## Behavioral controls and limits of the evidence

`control.ts` runs the same 14 fixtures against the actual decoder and renderer
under native Bun: **14/14 pass**. This checks that the intended cases are valid
and the expected cfg pairs are grounded in the actual renderer. It is not a
substitute for QuickJS results.

| Fixtures | Native Bun control | QuickJS |
| --- | --- | --- |
| Nested video sync/HDR/aspect ratio and audio rate/latency/volume | Pass, expected rendered values checked | Blocked before decode |
| Wrong video/audio types | Reject | Blocked before decode |
| Frame-delay / audio latency ranges, fractional integer | Reject | Blocked before decode |
| Unknown root and nested fields | Reject | Blocked before decode |
| Two valid HTTPS updater URLs | Accept and render | Blocked before decode |
| HTTP, malformed HTTPS, relative URL | Reject | Blocked before decode |
| Nullable URL | Accept | Blocked before decode |

The probe explicitly observes `TextEncoder`, `TextDecoder`, `URL`,
`URLSearchParams`, `setTimeout`, `setInterval`, `fetch`, `process`, and `require`
as `undefined`. It installs none of them. No timer behavior is tested because
initialization fails sooner.

## Remaining blockers and recommendation

1. **Verified:** importing this actual Effect graph needs `TextEncoder` before
   any decode. The public subpath and both tested bundlers do not remove that
   requirement. No evidence here supports raising production budgets.
2. **Source-inspected, not reached in QuickJS:** the next line of `Encoding.js`
   needs `TextDecoder`. Other module-init requirements can be hidden behind the
   first failure. Do not assume fixing one global completes the graph.
3. **Source-inspected, not reached in QuickJS:** `setting-policy.ts` uses native
   `new URL(value)` and catches construction failures as validation failures.
   QuickJS has no URL constructor here. Thus an unchanged validator would reject
   valid HTTPS if initialization were otherwise fixed. A real standards-correct
   implementation or an approved architecture decision is needed, not a fake
   parser. This probe does not add either.
4. **Verified product boundary:** `script.rs` currently has no loader, a 128 KiB
   TS limit and a 512 KiB JS limit. The graph loader used here is experimental;
   the aggregate graphs and non-minified bundles are not accepted single-source
   product inputs. The minified bundle fits the JS limit but still fails. An
   approved-source package loader/preparation boundary remains unimplemented.
5. **Unmeasured:** successful decoder latency, peak memory, passing heap cap,
   target-device performance, and any later runtime requirements. Bundling alone
   did not establish compatibility.

**Recommendation (judgment):** stop at this reproducible blocker. If option A
continues, first decide the permitted pure platform-library/preparation boundary,
then repeat the exact decoder fixtures with real implementations and no timer/I/O
grants. Cost: this adds dependency/security review and possibly runtime preparation
work; it does not yet solve package approval, URL conformance, or resource sizing.
Do not replace the Effect schema or increase production sandbox limits on the
basis of these measurements.
