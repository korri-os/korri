# Research: AR PR #2 lessons for native Simpsons dynamic aspect

## Summary

AR PR #2 offers a transferable separation of drawable size, requested view, valid rendered content, and final presentation. It does **not** supply Simpsons camera hooks or prove arbitrary native render resolution: ReXGlue already parses custom dimensions and exposes configured video modes, but those controls alone do not prove that Simpsons changes its projection or render targets.

Checked on 2026-10-05: downloaded primary-source PR metadata, all 1,665 lines of `pr.diff`, comments and reviews; maintainer-linked upstream commit metadata and the Auto diff; local Simpsons/ReXGlue source. No builds, gameplay tests, generated retail code publication, or target changes.

## Findings

1. **Verified PR state: closed, not merged, still marked draft.** Head is `1f11679d47f3f5933c8103b4ff32fab40ed1ccb9`; base is `e0179b3bbdf7a472cbdc90d9d2eadfe0956be199` on `fix/capture-and-clip-fixes`, not `main`. The snapshot records one commit, 38 changed files, +667/−94, and `merged_at: null`. The upstream author says they *reworked* both PRs into two linked commits; this is not evidence that this exact patch was merged unchanged. The reviews snapshot is empty. [PR](https://github.com/simonwjackson/ar-recomp/pull/2), [upstream comment](https://github.com/simonwjackson/ar-recomp/pull/2#issuecomment-5973341715)

2. **Verified implementation: bounded view expansion, not Stretch.** The diff appends `kScreenAspect_Auto = 4`, keeps 4:3 as default, and accepts `Auto`, `auto`, and `4`. `DisplayGeometry_ResolveAutoCanvas` uses 64-bit arithmetic to expand one axis of 256×224, with square or 7:6 CRT pixels. It rounds symmetric whole-pixel margins and caps each side at 120 columns or 64 rows. At 1240×1080 it requests 256×260 for CRT pixels, or 258×224 for square pixels. Extreme shapes can retain borders. This reuses existing ActRaiser extension machinery; it does not implement a generic arbitrary-resolution renderer. [Geometry at PR head](https://github.com/simonwjackson/ar-recomp/blob/1f11679d47f3f5933c8103b4ff32fab40ed1ccb9/src/present/display_geometry.c), [actual diff](https://github.com/simonwjackson/ar-recomp/pull/2/files)

3. **Verified implementation: coherent geometry across the pipeline.** `host_display.c` reads renderer output pixels, preserves the previous budget for an invalid/minimized drawable, and prevents Auto from calling `SDL_SetWindowSize`. Budget changes clear output buffers, rebind PPU output, and invalidate presentation history. Settings reconciliation does not rewrite Auto's saved display profile. `FrameSlot` stores requested height/top separately from bounded capture margins. `CaptureDestination` places captured rows at their original scale within the requested canvas; unavailable rows remain clear. Texture and effect-mask heights accommodate expanded captures. Effects, HUD, replacement art and Diorama fit use the requested geometry; the authentic comparison remains 256×224. [Host](https://github.com/simonwjackson/ar-recomp/blob/1f11679d47f3f5933c8103b4ff32fab40ed1ccb9/src/host/host_display.c), [frame capture](https://github.com/simonwjackson/ar-recomp/blob/1f11679d47f3f5933c8103b4ff32fab40ed1ccb9/src/present/frame_slot.c), [placement](https://github.com/simonwjackson/ar-recomp/blob/1f11679d47f3f5933c8103b4ff32fab40ed1ccb9/src/render/presentation_layout.c)

4. **Verified boundary: world visibility is game-specific.** Auto is scoped to action scenes, excluding native-framed non-action scenes and Mode 7. Per-layer room bounds limit valid extra rows; BG3 stays native-only to prevent HUD/title tilemap wrapping. Auto enables object/component *drawing* independently of old 4:3 flags. Activation retains its saved preference. Thus a retained FULL profile can change gameplay relative to authentic 4:3; a larger view is not automatically simulation-neutral. ActRaiser's map, WRAM, tilemap and sprite seams are not Simpsons addresses or algorithms. [Frame policy](https://github.com/simonwjackson/ar-recomp/blob/1f11679d47f3f5933c8103b4ff32fab40ed1ccb9/src/actraiser/enhancements/actraiser_frame_plan.c), [sprite policy](https://github.com/simonwjackson/ar-recomp/blob/1f11679d47f3f5933c8103b4ff32fab40ed1ccb9/src/actraiser/enhancements/actraiser_widescreen_sprites.c)

**Recommendation (inferred):** transfer AR's geometry ownership and validation approach, not its SNES constants or hooks. Keep drawable size, game view aspect, internal render resolution, UI framing and presentation aspect distinct. Follow drawable changes without resizing the window back or rewriting saved preferences. Pair geometry with each frame and audit stale/history resources when geometry changes. Cost: more synchronization and resource-lifecycle work; this alone does not solve projection, culling or performance.

**Required Simpsons-specific investigation:** trace where the game consumes video mode, chooses camera projection/FOV, creates render targets, sets viewports/scissors, and selects visibility. Audit HUD/menu coordinates, split-screen, scripted cameras, videos and post-processing separately. Confirm whether each path caches startup dimensions or supports live changes. Prefer handwritten function overrides over generated-file edits, as upstream requests. No Simpsons hook address was established here. [Upstream contribution guidance and widescreen roadmap](https://github.com/YesterMester/TheSimpsonsGameRecomp/blob/f63f57bcba29d3e7016fd867fad05adc85822bcb/README.md)

## Review and test limits

- **Verified test code, not rerun results:** the new ROM-free test checks solver rounding, caps, invalid sizes, and actual SDL software-renderer upload/readback with asymmetric missing rows. Other changed tests cover retained profiles, draw-versus-activation gates, BG3 clipping, masks, effects, HUD and authentic comparison. [Test](https://github.com/simonwjackson/ar-recomp/blob/1f11679d47f3f5933c8103b4ff32fab40ed1ccb9/tests/auto_canvas_test.c)
- **Author-reported only:** 22 affected tests pass; full CTest passes 305/311, with six claimed baseline failures. Nine baseline render scenes are byte-identical, but none selects Auto. GPU evidence used the branch **plus an additional diagnostics commit**, not the exact PR head. Reported Mini V2 CRT output is 1240×1079, not exact full-height fill. [PR evidence](https://github.com/simonwjackson/ar-recomp/pull/2)
- **Coverage limits:** extra rows reuse endpoint scanline state without advancing HDMA/callbacks; author checked Aitos 04/04 and 04/05 only. Known issues include Diorama edge gaps and native-height inspector picking. No formal review or independent test run is present in the supplied review snapshot. These results do not validate Simpsons on any aspect or device.
