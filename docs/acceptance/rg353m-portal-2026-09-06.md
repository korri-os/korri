Nix profile generations without rebuilding or switching the operating system.

## Thermal behavior and fixes

**Policy change:** the user requested removal of the portal guard after these
checks. The device composition no longer defines it. Linux thermal management
is unchanged. The stops described below are historical, not current policy.

The guard-free closure is installed for the next boot:
`/nix/store/vz40dmvqyy02iwmp3w57aqlwh3kahy55-nixos-system-rg353m-sd-card-26.05.20251221.a653104`.
Its guard unit and kiosk Wants link are both absent. Kernel, module and DTB
links and the Sunshine/compositor/kiosk unit files match the preceding runtime.
The running old unit is stopped and prevented from starting by a temporary
`ConditionPathExists=!/` drop-in. Chromium and Sunshine are active. No reboot was
forced for this change; the guard-free closure has not yet been boot-tested.

The initial Chromium GPU process repeatedly crashed on seccomp syscall `0x77`.
Explicit ANGLE/GLES flags did not fix it. The guard stopped the browser at
68.125°C while Sunshine stayed running.

The RG353M now supplies `--disable-gpu` and `--force-prefers-reduced-motion` as
actual Chromium arguments. The browser sandbox stays enabled. Both surfaces
passed interaction checks with these arguments. Across 31 samples over 323
seconds, temperature ranged from **43.75°C to 55.555°C**, ending at 44.375°C.
No GPU crash appeared in that browser invocation. This is a short fixture-workload
check, not a sustained animation or gaming benchmark.

One hot reboot reached 68.75°C before Chromium opened. The guard stopped it as
specified. An operator restarted it only after cooling to 44.375°C. That manual
restart is **not** counted as automatic boot verification.

A separate cooled reboot exposed a dependency defect: Sway's first invocation
failed to open `renderD128`, then recovered, but the kiosk stayed inactive after
its failed dependency job. The kiosk is now wanted by its compositor and nginx,
so a later parent start pulls it back in. The underlying DRM permission timing
issue remains a separate hardware follow-up; this slice changes no permissions.
